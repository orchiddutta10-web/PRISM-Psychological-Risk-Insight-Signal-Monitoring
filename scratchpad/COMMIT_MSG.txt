fix(e2e): resolve 3 BROKEN + 3 SUSPECT issues from end-to-end health check

A fresh end-to-end audit (import every Python module, probe every
endpoint, compile the dashboard, load every .joblib) found 3 broken
items, 3 suspect items, and 5 notes. This commit fixes the broken
and suspect items so the project compiles + runs clean.

## Broken → fixed

### 1. PRISM_MODEL_DIR pointed to a non-existent directory
`config.py` defaulted `PRISM_MODEL_DIR` to `API_DIR / "resources" /
"prism"` (one level above `app/`). The actual artifacts live at
`API_DIR / "app" / "resources" / "prism"`. Result: `/api/v1/prism/predict`
returned 503 with `reason=model_not_loaded` even though all 3 artifacts
were present and loadable.

Fix: corrected the default path. End-to-end smoke test now returns
200 with full 57-feature inference (classifier + regressor + data
sufficiency + feature_status + model_version).

### 2. `app/ml_pipeline/feature_store.py` couldn't import
Referenced `SensorReading`, `BehaviorWindow`, `PhoneEvent` from
`app.models` — none of those classes exist post-iot migration. SQLite
has the legacy tables but no ORM mapping.

Fix: added the 4 legacy ORM classes back to `app/models.py`
(`SensorReading`, `PhoneEvent`, `BehaviorWindow`, `RiskScoreV2`)
so the dormant Phase 8/12 archival code keeps working against the
~250K legacy rows already in `prism.db`. New ingestion continues to
write to `RawSignalEvent` / `BaselineProfile`.

### 3. 22 TypeScript compile errors in the dashboard
Pages imported `apiFetchSafe`, `timeAgo`, `severityOf`, `ChildDevice`,
`BackendAlert`, `IngestionHealth`, `clearAuth`, `setSelectedDevice`,
`getGuardian`, `getToken`, `API_BASE` from `@/lib/api` — none of them
were exported.

Fix: added all 11 missing exports to `apps/dashboard/src/lib/api.ts`
plus a robust `readJsonLocalStorage` helper, with JSDoc describing
when to use the React `useAuth()` context vs the standalone helpers.
Also fixed:
- `app/lib/auth-context.tsx` now imports `API` (not `API_BASE`)
- `(dashboard)/devices/page.tsx` now correctly flattens the
  `active_modalities` API response into `{name: status}` before
  calling `setModalities`

Result: `npx tsc --noEmit` → 0 errors (was 22).

## Suspect → fixed

`app/utils/{prism_ml_engine,production_feature_builder,drift_monitor}.py`
each referenced `_m.SensorReading / BehaviorWindow / PhoneEvent /
RiskScoreV2` from the missing model classes. They are still
unreachable (the iot merge deleted `routes/ml.py` and the `/api/v1/ml/*`
endpoints), but with the legacy ORM classes restored above they
won't 500 if anyone wires them back up.
